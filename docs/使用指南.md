# CallFence 使用指南

日期：2026-10-06

CallFence 是離線的前端請求契約檢查器。給它 OpenAPI 3.1 JSON 與前端呼叫範例，就能看到路徑、方法、必要參數或 JSON 欄位是否對得上；來源證據包含檔名、SHA-256 與 JSON Pointer。

## 安裝與展示

```sh
git clone https://github.com/Wayne725/callfence.git
cd callfence
python -m venv .venv
source .venv/bin/activate
python -m pip install .
callfence demo --out runs/demo
```

Windows PowerShell 啟用環境：`.venv\Scripts\Activate.ps1`。直接開啟 `runs/demo/report.html`，不用啟動伺服器。

展示有 9 個合成呼叫。基準版本全部通過；候選版本 7 個失敗、1 個待人工確認、1 個通過。點選「Confirm an uploaded file」可查看舊欄位 `file_size` 與新規則 `size_bytes` 的矛盾，切換 Baseline／Candidate 可回看前後版本；「Keep the delivery choice」展示欄位沒宣告時的政策檢查。

## 正式作為檢查使用

```sh
callfence check openapi.json consumer.json --out runs/current
callfence compare old-openapi.json new-openapi.json consumer.json --out runs/release
```

每次用新的輸出資料夾。輸入不會修改，既有輸出拒絕覆寫。

`consumer.json` 使用版本 1，包含消費端名稱與 1～100 個案例。每個案例要有唯一 `id`、`title`、`method`、`path`；參數放在 `parameters`，JSON 主體放在 `body`。完整例子在 `src/callfence/examples/consumer.json`。

路徑要包含 `/v1` 等實際 API 前綴，不放主機網址、查詢字串或 fragment。參數路徑用模板 `/v1/batches/{batch_id}`，範例值放在 `parameters.path.batch_id`；後端名稱改為 `{id}` 可按位置對應，但不會把實際網址 `/v1/batches/42` 自動推成模板。

參數範例是「型別已還原的 JSON 值」，整數要寫 `20` 而非 `"20"`。它不驗證 HTTP 字串序列化。JSON 主體省略與寫成 `null` 是不同的情境。

## 政策與判讀

- `declared_body_fields: true`：要求 JSON 物件的最外層欄位名稱已宣告，協助找出疑似會被忽略的欄位。不是完整巢狀欄位檢查，也不代表後端真的忽略或拒絕它。
- `declared_parameters: true`：要求送出的參數名稱已宣告。不是宣稱未宣告參數違反 HTTP。

兩項政策預設為 false，展示明確開啟。

候選失敗、基準通過才標為 New failure；兩邊都失敗為 Existing failure；修好為 Fixed；兩邊通過為 Stable。任一版本含驗證不了的內容，標 Need review，保留已知錯誤。

`check`／`compare` 回傳 0 代表全部範例在支援的範圍內通過；1 代表有失敗或待人工確認，仍會寫報告；2 是輸入或輸出錯誤。`compare` 基準有問題也會回傳 1，不能用候選修好掩蓋不健康的基準。

`demo` 只是產生展示，成功回傳 0；展示的 manifest 會記錄實際檢查結果 1。CI 應使用 `check`／`compare`，不能把 `demo` 當驗收。

## 輸出與邊界

`report.html` 是互動介面；`results.json` 是完整證據；`junit.xml` 可交給 CI；`manifest.json` 保存輸出雜湊。報告會帶入來源值，請用去識別範例，並按來源資料的敏感程度保存。

第一版僅支援 OpenAPI 3.1.0／3.1.1 JSON、明確的 `application/json` 主體與純量參數。不呼叫 API、不讀取 Token、不檢查回應或真實後端、不自動分析前端程式。認證、外部／遞迴引用、部分特殊 schema 與序列化設定會轉為待人工確認，不能算通過。完整支援與限制見 [SPEC.md](SPEC.md)。

這件作品適合展示：前後端整合診斷、代表案例整理、可追查的失敗證據與 CI 防回歸。真實流程仍需整合測試；範例全過不能證明所有呼叫都相容。
